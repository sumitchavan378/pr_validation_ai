Here’s what was added and changed so reviews run only from GitHub Actions when a PR targets qa (no local server required).

1. Workflow — .github/workflows/virtual-review-board-qa.yml
At the repo root (PR_Validation/), next to your virtual-review-board/ app:

Triggers: pull_request with opened, synchronize, reopened when the base branch is qa (PRs into qa).
Job: checkout → Python 3.12 → pip install -r virtual-review-board/requirements.txt → python -m app.ci_review with working-directory: virtual-review-board.
Permissions: contents: read, pull-requests: write, checks: write.
Concurrency: one run per PR; newer pushes cancel the old job.
You must add a repository secret GOOGLE_API_KEY (Google AI Studio). GITHUB_TOKEN is provided by Actions automatically.

2. CI entrypoint — app/ci_review.py
Reads GITHUB_EVENT_PATH and GITHUB_REPOSITORY, checks the same actions as the webhook (opened / synchronize / reopened), then runs the same review path as before.

3. Shared pipeline — app/review_pipeline.py
execute_pr_review(...) is used by both the FastAPI background task and CI so behavior stays in sync.

4. Config / security
GITHUB_WEBHOOK_SECRET defaults to empty (fine for Actions).
verify_github_signature returns False if the secret is empty`, so the HTTP webhook cannot be used without configuring a real secret.
5. Docs
virtual-review-board/README.md now has a “GitHub Actions (QA branch)” section: secret setup, monorepo vs single-folder repo, fork limitations.

What you do on GitHub

Push this tree (including .github/workflows/virtual-review-board-qa.yml).
Settings → Secrets and variables → Actions → New repository secret: GOOGLE_API_KEY.
Use a qa branch as the target of PRs you want reviewed.
